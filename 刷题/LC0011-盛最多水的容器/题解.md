# LC0011 盛最多水的容器 题解

- **难度**：中等
- **核心考点**：双指针（左右夹逼）、贪心正确性证明
- **复杂度**：O(n) 时间 / O(1) 空间
- **验证**：9 个固定用例（含官方样例 49）+ 300 随机 vs O(n²) 暴力全部一致（C/C++ 双版）；n=10⁵ 时 C 0.39s / C++ 0.28s

---

## 一、问题转化

两条线 i < j 形成的容器：

```
容量 = min(height[i], height[j]) × (j - i)
```

**短板效应**：容量被"矮边"卡死——无论高边多高，水只能装到矮边的高度。

## 二、双指针算法（主解）

```
l = 0, r = n-1, best = 0
while (l < r):
    area = min(h[l], h[r]) * (r - l)
    best = max(best, area)
    if h[l] < h[r]: l++     # 矮边在左，左指针右移
    else:            r--    # 矮边在右，右指针左移
```

**为什么移动矮边而不是高边？**

当前窗口 [l, r]，容量 = min(h[l], h[r]) × (r−l)。

- 如果移动**高边**：宽度一定变小，而高度还是被矮边卡着（min 不变）→ 容量只减不增，**移动高边永远不优**
- 如果移动**矮边**：宽度变小，但**有机会遇到更高的边**，容量可能变大

所以每次只移动矮边，就是"用宽度换潜力"，把最可能产生更大容量的方向保留下来。

## 三、为什么贪心不丢解（反证）

假设最优解是 (L, R)，双指针扫描中第一次出现"矮边被移动且该矮边是 L 或 R"的情况：

- 若矮边在 L 侧（h[l] ≤ h[r]）：此时 r > R（否则早该到了），且 h[l] ≤ h[R]（否则 l 不该是最优解左边界的候选……严谨推导：以 l 为左边界的任意容器 (l, x)，x ≤ r，其容量 ≤ min(h[l], h[r]) × (r−l) 的演变过程……）
- 核心一句话：**当矮边在 L 侧时，任何以 L 为左边界的容器都不会超过最优解**（因为另一边 ≤ R 时宽度更小，另一边 > R 时高度 ≤ h[L] ≤ h[R]），所以丢掉 L 不丢最优解。对称地处理 R。每一步都安全，最后必达最优解。

## 四、复杂度

- 时间 O(n)：l、r 相向而行，各走 n 步
- 空间 O(1)

## 七、易错点清单

| 坑 | 正确姿势 |
|----|----------|
| 移动高边 | 高边移动宽度必减、高度被矮边卡死，永远不优 |
| 高度相等时随意移动 | 相等时移哪边都行（结果相同），但要**保证每次只移一边** |
| 面积公式写反 | min(高) × (r−l)，不是 max(高) × (r−l) |
| 忘记更新 best | 每次窗口变化都算一次面积并更新 |
| 用暴力 O(n²) 硬算 | n=10⁵ 会超时，双指针 O(n) 才是正解 |
