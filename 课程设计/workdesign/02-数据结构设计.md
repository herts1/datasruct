# 题目3：电话"聊天狂人"查询系统 —— 数据结构设计

## 一、总体设计思路

本系统采用**哈希表**作为核心存储结构，针对两种不同的关键字（手机号码、姓名）分别建立哈希表，并实现两种哈希函数和两种冲突处理方法的对比分析。

## 二、核心数据结构定义

### 2.1 顾客信息结构体 (`Customer`)

```c
typedef struct {
    char name[NAME_LEN];      // 姓名，最大32字符（支持中文）
    char id[ID_LEN];          // 身份证号，18位 + '\0'
    char phone[PHONE_LEN];    // 手机号，11位 + '\0'
    int  call_count;          // 通话次数（主叫+被叫）
} Customer;
```

| 字段 | 类型 | 长度 | 说明 |
|------|------|------|------|
| `name` | `char[]` | 32 | 中英文姓名，以`\0`结尾 |
| `id` | `char[]` | 19 | 18位身份证号 |
| `phone` | `char[]` | 12 | 11位手机号 |
| `call_count` | `int` | 4字节 | 通话次数统计 |

### 2.2 开放寻址法槽位 (`OASlot`)

```c
typedef struct {
    int valid;      // 状态标记：0=空, 1=已占用, 2=已删除
    int cust_idx;   // 指向 customers[] 数组的下标
} OASlot;
```

**状态标记含义**：

| valid值 | 状态 | 说明 |
|---------|------|------|
| 0 | 空 (EMPTY) | 从未被占用 |
| 1 | 占用 (OCCUPIED) | 当前存有数据 |
| 2 | 删除 (DELETED) | 曾经有数据，已被逻辑删除 |

> 引入"删除"标记是为了保证线性探测查找链的连续性——遇到DELETED不终止查找，继续向后探测。

### 2.3 链地址法节点 (`ChainNode`)

```c
typedef struct ChainNode {
    int  cust_idx;              // 指向 customers[] 数组的下标
    struct ChainNode *next;     // 指向同义词链表的下一个节点
} ChainNode;
```

**链表结构特点**：
- 采用**头插法**插入（O(1)复杂度）
- 同一桶内的节点通过`next`指针形成单链表
- 每个桶（`table[i]`）为链表头指针，初始为`NULL`

### 2.4 哈希统计结构体 (`HashStats`)

```c
typedef struct {
    int  collisions;    // 冲突次数
    long total_probe;   // 总探测次数（用于计算ASL）
    int  inserted;      // 成功插入数量
} HashStats;
```

## 三、全局数据组织

### 3.1 主数据数组

```c
Customer customers[MAX_CUSTOMERS];  // 顾客主表，最大100条
int      cust_cnt = 0;              // 实际顾客数量

char call_from[MAX_CALLS][PHONE_LEN]; // 主叫方号码
char call_to[MAX_CALLS][PHONE_LEN];   // 被叫方号码
int  call_cnt = 0;                     // 实际通话记录数
```

### 3.2 四套哈希表实例

```c
// 手机号哈希表
OASlot    phone_oa[PHONE_TABLE_SIZE];   // 开放寻址（线性探测）
ChainNode *phone_ch[PHONE_TABLE_SIZE]; // 链地址法

// 姓名哈希表
OASlot    name_oa[NAME_TABLE_SIZE];    // 开放寻址（线性探测）
ChainNode *name_ch[NAME_TABLE_SIZE];   // 链地址法
```

**设计意图**：同时维护四套哈希表，使得"冲突率比较"和"ASL比较"可以在同一组数据上独立进行，无需反复重建。

## 四、哈希表参数设计

### 4.1 表长选择

| 表 | 大小 | 选择依据 |
|----|------|---------|
| `PHONE_TABLE_SIZE` | **61** | 质数，能减少除留余数法的聚集效应 |
| `NAME_TABLE_SIZE` | **61** | 质数，同上 |

- 当前数据量 30 条，装填因子 α = 30/61 ≈ 0.49
- 理论ASL（成功查找，线性探测）：≈ 1.49
- 理论ASL（成功查找，链地址法）：≈ 1.25

### 4.2 哈希函数索引

```c
#define HASH_DIV   0    // 除留余数法
#define HASH_FOLD  1    // 折叠法
```

## 五、存储结构选型依据

### 5.1 为何选择哈希表？

| 对比维度 | 顺序表/链表 | 二叉排序树 | 哈希表 ✓ |
|----------|-----------|-----------|----------|
| 按手机号查找 | O(n) | O(log n) | **O(1)** |
| 按姓名查找 | O(n) | O(log n) | **O(1)** |
| 插入 | O(1) / O(n) | O(log n) | **O(1)** |
| 空间开销 | 小 | 中 | 中 |
| 实现复杂度 | 低 | 中 | 中 |

题目要求"快速查询"，哈希表是最合适的选择——查找和插入均摊O(1)。

### 5.2 为何选择两种冲突处理方法？

1. **开放寻址法（线性探测）**：实现简单，缓存友好，适合装填因子较小的情况
2. **链地址法**：装填因子可大于1，删除操作简单，适合数据量不确定的场景

两者对比可以直观展示不同冲突处理策略的优劣。
