# 题目3：电话"聊天狂人"查询系统 —— 题目要求分析

## 一、题目来源

《数据结构》课程设计任务书 —— 题目3（满分70分）

## 二、问题描述

通讯公司提供优惠通话套餐服务，当顾客通话时长累积达到一定数量后，可享受更高折扣或积分兑换等奖励。现给定大量手机用户通话记录，一条记录以**拨出方**和**接收方**的11位手机号码为标识，要求根据手机号码快速查询通话次数最多的"聊天狂人"。

## 三、核心功能要求

| 序号 | 功能 | 说明 |
|------|------|------|
| 1 | 哈希表构建 | 姓名以汉字形式输入，约30人。分别以**手机号码**和**姓名**为关键字建立两个哈希表 |
| 2 | 查找"聊天狂人" | 查找并显示通话记录中通话次数最多的用户（手机号码、姓名、通话次数） |
| 3 | 按姓名查询 | 查找并显示给定姓名的通话记录、身份证号码和手机号；不存在则输出 `No Info` |
| 4 | 哈希函数比较 | 设计至少2种不同的哈希函数，观察不同数据量下的**冲突率**，在界面上给出比较结果 |
| 5 | 冲突处理方法比较 | 在哈希函数确定的前提下，尝试不同类型处理冲突的方法，用统计方法观察**平均查找长度(ASL)**的变化 |

## 四、数据文件

| 文件 | 内容 |
|------|------|
| `customers.txt` | 顾客信息：姓名（拼音）、身份证号码（18位）、手机号（11位） |
| `calls.txt` | 通话记录：拨出方手机号、接收方手机号 |

## 五、约束条件

1. **数据量要求**：不少于30条顾客记录
2. **存储结构**：必须使用**哈希表**作为内存存储结构
3. **哈希函数**：至少设计**2种**（当前实现：除留余数法、折叠法）
4. **冲突处理**：至少实现**2种**（当前实现：线性探测开放寻址法、链地址法）
5. **姓名输入**：汉字形式
6. **主菜单**：界面友好，支持反复操作

## 六、现有实现分析

现有代码（[main.cpp](main.cpp)、[phone.h](phone.h)、[phone.c](phone.c)）已实现的功能：

### 6.1 数据结构

```
哈希表大小：
  - 手机号哈希表：61（质数）
  - 姓名哈希表：61（质数）

顾客容量：MAX_CUSTOMERS = 100
通话记录容量：MAX_CALLS = 500

两个并行的哈希表集合：
  - 开放寻址法（OA）：phone_oa[61]、name_oa[61]
  - 链地址法（CH）：phone_ch[61]、name_ch[61]
```

### 6.2 两种哈希函数

| 方法 | 宏定义 | 手机号处理 | 姓名处理 |
|------|--------|-----------|---------|
| 除留余数法 | `HASH_DIV` | 11位数字转`unsigned long`后取模 | 字符乘31累加后取模 |
| 折叠法 | `HASH_FOLD` | 前3位+中4位+后4位求和取模 | 每4字符一组拼接后累加取模 |

### 6.3 两种冲突处理方法

| 方法 | 宏定义 | 查找策略 |
|------|--------|---------|
| 线性探测开放寻址 | `PROBE_LINEAR` | 步长step=0,1,2,...线性探测 |
| 链地址法（拉链法） | `PROBE_CHAIN` | 头插法构建单链表 |

### 6.4 菜单功能

```
1. 查询"聊天狂人"（通话次数最多者）
2. 按姓名查询用户信息及通话记录
3. 按手机号查询用户信息
4. 比较两种哈希函数的冲突率
5. 比较两种冲突处理方法的ASL
0. 退出
```

### 6.5 现有数据规模

- 顾客：30条（刚好满足最低要求）
- 通话记录：46条
